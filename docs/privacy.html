Privacy Policy

Effective date: 29 October 2026 — applies to DSH Mail Connector 1.3.0 and later.

DSH Mail Connector ("the server") is a locally operated Model Context Protocol server. This policy describes the behaviour of the published server implementation.

Who operates it

The server is not a hosted service and has no operator-side backend. Whoever installs and runs it controls it on their own computer; this page describes the software, not a cloud account.

Google data accessed

After the user grants consent, the server can access their Gmail and Google Calendar data through Google APIs, limited to these four scopes:

  • gmail.modify — read messages and labels; add or remove labels; archive, trash and restore messages; create drafts.
  • gmail.settings.basic — read, create and delete the account's Gmail filter rules.
  • calendar.events — create, update and delete calendar events.
  • calendar.readonly — list calendars, read events and query free/busy information.

The implemented tools cover search, read, download, draft creation, label and filter management, trash and restore, and calendar event management. The server has no send-mail tool and no permanent-delete route.

How the data is used

Data is used only to carry out actions the user starts through their MCP client: returning search results and message content, saving a message or attachment to the configured download folder, changing labels or trash state, creating a draft, or reading and writing calendar events. Nothing is used for advertising, profiling or analytics.

Where data is stored

OAuth credentials (a refresh token and the OAuth client details) are stored in a local credential file; messages and attachments are written only to a local download folder the user chooses. The server keeps no cloud database, no telemetry and no server-side logs of message content.

Sharing and AI services

The server itself sends data only to Google APIs (Gmail, Calendar and the OAuth token endpoint). When a mail or calendar item is returned through an MCP client or AI assistant, that client — not this server — decides what happens to it; depending on its configuration it may send the content to a third-party AI model provider. Users should review their assistant's data-processing and retention terms before connecting it.

Retention and deletion

Local credentials and downloaded files remain on the user's computer until the user or administrator deletes them. Drafts, labels, filters, trash state and calendar events are stored by Google under the user's own Google account settings. Data the server never stores cannot be retained by it.

Revoking access

Access can be revoked at any time at Google Account connections; this invalidates the refresh token. To remove local copies, delete the credential file and the download folder.

Google API Services User Data Policy

The server's use of Google user data follows the Google API Services User Data Policy, including the Limited Use requirements: data is used only to provide the features described on this page, is not sold, is not used for advertising, and is not transferred to third parties except as needed to provide those features or as required by law.

Security

Credentials are written with owner-only permissions where the operating system supports them; OAuth uses PKCE and state verification; tokens are never printed or sent anywhere except Google's token endpoint.

Contact

Questions, data-deletion requests or security reports: open an issue on the project repository.
